Como usar o GHOSTRECON hoje

Este guia cobre o fluxo atual do GhostRecon: alvo, escopo, OPSEC, módulos, modo Kali, integração Vigolium, Codex, IA, findings, histórico, workbench e geração de relatório.

Inicio rapido

  1. Suba a interface: execute npm start e abra http://127.0.0.1:3847/.
  2. Informe o alvo: use o campo Target com domínio ou URL. Em modo arquivo, carregue uma lista.
  3. Defina o contexto: preencha projeto, contexto bounty, escopo, fora de escopo e operador quando fizer sentido.
  4. Escolha o perfil: use recon passivo para mapeamento leve, Full/deep para varredura mais completa e Kali/PATH quando houver ferramentas externas instaladas.
  5. Rode o recon: clique em RUN RECON. A saída aparece no terminal, nos cards e na área de findings.
  6. Revise e exporte: valide findings, abra Reporte/History/Vigolium Workbench e gere o pacote final.
No Windows puro, ferramentas Kali, Go e binários externos podem não existir no PATH. Nesse caso o GhostRecon usa os módulos internos. Para Vigolium PATH, nuclei, httpx, subfinder e fluxo Kali, rode em Kali, Linux ou WSL com as ferramentas instaladas.

Painel esquerdo

O painel esquerdo é o cockpit do recon. O botão ? ao lado do título abre uma explicação item por item dentro da própria UI. O botão Como usar traz você para esta página.

Alvo e projeto

Projeto, Contexto bounty, Target, fila de alvos e fora de escopo alimentam o pipeline, o histórico SQLite e os relatórios.

OPSEC

Engagement ID, operador, confirmação de ativo, perfil OPSEC, Navigator/Tor e rotação de identidade ajudam a controlar risco e rastreabilidade.

Execução

Modo anônimo, exact match, dorks, Full, Recon subs e perfil recon ajustam intensidade, ruído e profundidade da varredura.

Integrações

Auth, Kali, PATH, Ghostmap, Cortex, History, Vigolium, Reporte, GhostDesk e Pós-Exploração conectam o recon aos fluxos auxiliares.

Recon e módulos

O GhostRecon combina módulos internos com ferramentas externas quando elas estão disponíveis. A UI mostra módulos ativos, capacidades detectadas e logs de execução para você entender o que realmente rodou.

Use passivo para enumeração segura, full para ampliar cobertura, kali para delegar a ferramentas do ambiente e path para priorizar binários instalados.

  • Google Dorking/OSINT: abre consultas úteis e coleta pistas sem tocar diretamente o alvo quando possível.
  • Recon subs: aprofunda subdomínios, endpoints e sinais de exposição.
  • Verificação: módulos ativos validam status, títulos, tecnologias, headers, rotas e achados importados.
  • Kali: quando habilitado, tenta usar ferramentas no PATH antes de cair para comportamento interno.

Vigolium

A integração Vigolium agora tem dois caminhos: usar os recursos internos do GhostRecon ou delegar para o Vigolium instalado no PATH. Quando o binário existe, o GhostRecon coleta a saída, transforma em findings e mistura com o relatório atual.

Instalação no modo Kali/Linux

curl -fsSL https://vigolium.com/install.sh | bash

Depois da instalação, o modo PATH pode rodar comandos como:

vigolium scan -t https://example.com --strategy deep
vigolium scan -t https://example.com --only discovery --format html -o report.html

Codex + Vigolium

A instalação pode perguntar se o operador quer usar Codex. Avise no onboarding que Codex depende de login/plano compatível. O fluxo com OpenAPI pode usar: 

vigolium scan -T openapi.yaml -I openapi

Na UI, use as opções de Vigolium DAST, Vigolium com Codex, audit/swarm/autopilot e Auth Compare para escolher como a varredura será conduzida.

Autenticação

Quando o alvo exige sessão, informe cookies ou perfis de login no painel Auth. O modo externo aceita o padrão:

vigolium scan -t https://example.com \
  --auth "admin:Cookie:session_id=abc123" \
  --auth "user:Cookie:session_id=xyz789"
O Vigolium Workbench concentra comparação de capacidades, execução assistida, importação de relatórios externos e revisão dos resultados antes de mandar tudo para findings.

IA

A camada de IA apoia revisão, priorização e texto de relatório. Ela não substitui validação manual: use para triagem, narrativa, próximos passos e explicação de impacto.

  • IA relatórios: gera resumo executivo, impacto, evidência, recomendação e próximos passos a partir dos achados.
  • Gemini/OpenRouter/Claude/LM Studio: provedores podem ser configurados no backend por variáveis de ambiente.
  • Shannon: ajuda a estimar qualidade/sinal dos dados coletados.
  • PentestGPT: apoia raciocínio de exploração e checklist de validação quando configurado.
  • Vigolium com Codex: usa Codex como assistente do fluxo Vigolium quando instalado e autenticado.

Findings

A área de findings centraliza descobertas vindas dos módulos internos, Kali/PATH, Vigolium, importações e validações manuais. Use filtros, severidade, origem, badges Vigolium e busca para separar ruído de evidência real.

  • Validação: marque o que foi confirmado antes de enviar para relatório final.
  • Histórico: o SQLite preserva achados por alvo, fingerprint e sessão.
  • Importação: relatórios HTML/JSON externos podem entrar no fluxo e virar findings normalizados.
  • Ajuda: o botão ? dos findings explica filtros, badges, severidade e estados.

Relatórios e Reporte

O fluxo de Reporte usa os findings atuais, validações manuais e histórico local para montar pacote de bug bounty ou pentest. Para listas enormes, exporte JSON filtrado ou abra Reporte já limitado por severidade/validados.

  • Reporte: organiza achados, evidências, checklist e exportações.
  • Anotações: cria texto em Markdown a partir das validações confirmadas.
  • HTML Vigolium: relatórios gerados por --format html podem ser importados e comparados com o pacote GhostRecon.
  • SQLite: use recarregar da base quando abrir uma aba nova ou perder o pacote em sessão.

Problemas frequentes

  • Servidor offline: confirme npm start, porta 3847 e logs do backend.
  • Popup bloqueado: libere popups locais ou abra manualmente como-usar.html, reporte.html ou vigolium-workbench.html.
  • Ferramenta não encontrada: em Windows puro é esperado que Go/Kali/Vigolium não existam. Instale no Kali/Linux/WSL ou use módulos internos.
  • Codex não roda: confirme instalação, login e plano compatível antes de usar Vigolium com Codex.
  • Auth não aplicado: confira formato de cookie, domínio, perfil selecionado e se o alvo realmente reutiliza aquela sessão.
  • SessionStorage cheio: exporte JSON filtrado, use Reporte por severidade/validados ou recarregue dados da SQLite.
  • Tor/Navigator falha: em Windows sem Tor instalado a checagem pode falhar; isso não impede recon interno.
  • Escopo divergente: se o host do pacote for diferente do alvo, confirme antes de gravar na base ou gerar reporte.
